# Security Policy

## Supported Versions

The first planned Hell release is `0.1.0`; no Hell release has been published
by this migration. Before the first release, the fork maintainers must define
the supported-release policy and a private reporting channel.

## Reporting a Vulnerability

A private vulnerability-reporting channel for Hell has not yet been verified.
Before publishing, maintainers must enable and verify private vulnerability
reporting for [gsmlg-dev/hell](https://github.com/gsmlg-dev/hell/security/advisories)
or document a confirmed private contact here. Do not post vulnerability details
in public issues. The upstream project's reporting contact is not a Hell contact;
Hell reports should not be sent to upstream maintainers.
